# Локальная модель и контекст

Этот путь предназначен только для dev-запуска API на хосте рядом с Ollama. Все запросы модели идут на `http://localhost:11434/v1`; трассировка отключена.

Docker запускается командой `OPENAI_MODEL=scripted:auto make stack` и не использует Ollama. Передача запросов из контейнера в Ollama хоста не настроена; установка live-модели в окружении контейнера не включает такой доступ. В Docker остаётся настоящее CPU-распознавание, поэтому речевые модели всё равно нужны. Демонстрационный алгоритм выбирает максимум три кандидата и не является проверкой качества генерации Qwen.

После установки `qwen3.5:4b` в локальном Ollama выполните:

```bash
make llm
OPENAI_MODEL=protokol-qwen3.5:4b make api
```

`make llm` создаёт отдельное имя модели с контекстом 16384 токена. Веса переиспользуются локально; скрипт не скачивает модель и не меняет исходное имя `qwen3.5:4b`. Для второй установленной модели:

```bash
backend/scripts/configure_ollama.sh qwen3:4b-instruct-2507-q4_K_M
OPENAI_MODEL=protokol-qwen3:4b-instruct-2507-q4_K_M make api
```

Если API уже запущен, перезапустите его с указанным `OPENAI_MODEL`. Проверить выбранную модель можно через `/api/health`. Фактический размер загруженного контекста показывает `ollama ps`.

## Почему нужен увеличенный контекст

На записи `m-sample-1` исходная конфигурация Ollama использовала контекст 4096 токенов. Зафиксированный ответ содержал `prompt_tokens=3233`, `completion_tokens=863`, `finish_reason=length`: JSON протокола был обрезан при достижении общего лимита. Увеличение только `max_tokens` запроса не увеличивает контекст модели. В OpenAI-совместимом API Ollama размер контекста задаётся конфигурацией модели.

Агент сначала читает сведения о встрече и стенограмму инструментами, затем формирует структурированный ответ. Перед подтверждением сервер проверяет принадлежность цитат встрече, факт чтения этих цитат в текущем запуске, говорящего и нормализует сроки. Успешный разбор JSON сам по себе не доказывает точность извлечения: поручения нужно просмотреть перед подтверждением.

Для длинных встреч общий объём входа и ответа всё ещё ограничен контекстом. Не завершённый JSON отклоняется; частичный протокол не сохраняется как подтверждённый.

`OPENAI_MODEL=scripted:auto` остаётся отдельным демонстрационным режимом без Ollama. Он выбирает не более трёх цитат с распознанным сроком и не заменяет генерацию протокола языковой моделью.

## Проверка исправления

На локальной записи `m-sample-1` после настройки 16K два зафиксированных последовательных запуска вернули статус `proposed` и по девять поручений. Первый завершился за 33,5 секунды; финальный запрос использовал 3233 входных и 1566 выходных токенов, `finish_reason=stop`. Это проверка устранения обрыва JSON, а не оценка полноты и точности поручений.

Полный повторный API-сценарий с окончательной конфигурацией: 11 поручений за 30,5 секунды, подтверждение перешло в `verified`, PDF (58 793 байта) и DOCX (40 347 байт) успешно выгружены. `/api/health`: защита включена, заблокированных внешних соединений 0. При несовпадении указанного поручившего с говорящими процитированных сегментов сервер оставляет поручившего неуказанным и показывает предупреждение; имя ответственного сохраняется.

Эти замеры показывают работоспособность конкретных запусков. Ручная оценка выявила ошибки исполнителей, неполные цитаты и расхождения сроков: [аудит двух записей](../evaluation/organizer/accuracy-summary.md). В Docker отдельно проверен путь с одним кандидатом, подтверждением и PDF: [результат](../evaluation/docker-smoke.json).
